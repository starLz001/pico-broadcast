# 硬性规则（红线）

实现任何任务卡时都必须遵守。违反任一条 = 评审必然打回。

## 计费与账本（最高优先）

1. **幂等用机制保证，不用"先查再插"**：launchId 必须是数据库唯一键（或等效约束），重复上报由约束拒绝，不是应用层判断。
2. **先校验额度，后拉起应用**——顺序不得颠倒。
3. **免单判定三步**：开局冻结 1 次额度 → 时长 ≤ 阈值（默认 8 分钟，云端可配）解冻不扣 → 超阈值确认扣减。冻结期间额度显示为占用。
4. 账本每行必须带签名字段；云端入库前验签，失败拒绝并记审计日志。
5. 补传队列与实时上报共用同一幂等键；补传不成功必须留在队列，不得丢弃。
6. 无指令的前台应用记录必须照常入账，`source=manual_detected`，并触发告警——不得静默忽略。

## 安全

7. Agent 执行任何指令前校验来源（token/签名），来源不明的指令丢弃并记日志。
8. 密钥、凭证、token 不硬编码、不写日志、不进错误提示。
9. 不留调试后门：无硬编码测试账号、无跳过鉴权的开关（开发环境的 mock 必须编译期隔离）。

## 工程

10. 任务卡「不做」清单中的内容一律不实现。
11. 不引入任务卡未声明的第三方依赖；确有必要 → STOP 回报。
12. 测试必须能独立重复运行（不依赖特定机器状态、不依赖上一次运行的残留数据）。
