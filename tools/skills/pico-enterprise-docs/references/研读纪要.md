## 2. 核心发现（按主题）

### 2.1 企业级 API / TobService —— Agent 的能力地基

- **集成方式**：Maven 依赖 `tobservicelib`（仓库 `artifacts-cn-beijing.volces.com/repository/picoxrtob`），接口通过 TobService 系统服务调用。
- **高风险接口**：需在 manifest 声明 `<meta-data android:name="pico_advance_interface" .../>`；**声明后应用不能上架 PICO 商店**——我们走企业分发，不受影响，但属合规红线。
- **开机自启**：Service 配置 Action `com.pvr.tobservice.SERVICE_AUTO_BOOT`，行业设置启动时拉起——Agent 常驻的官方通道。
- **Device Owner**：`setDeviceOwner` 接口（PUI 5.13.0+，PICO 4 Ultra E 已支持），是防篡改（防卸载/锁设置/限安装来源）的前提。
- **适用设备**：Neo3 Pro/eye、Neo3 企业版、PICO4E、**PICO4UE**、G3 等企业版型号；消费版不可用。

### 2.3 企业应用套件（官方播控方案）—— 我们的对标与差异

- **PC 播控方案**：设备管理（在线/电量/画面监控/**最高 25 路**/查找设备/校准视野/语音通话/音量/开关屏/关机重启/批量操作）；播控（视频 2D/3D/180/360 循环 + 进度回调、应用包名起停 + JSON 参数、全景图）；受控模式。
- **部署**：离线部署（`pre_resource` 目录拷设备根目录）/ 在线部署（单包 ≤10G，5 台并行）。
- **硬件网络要求**：PC i7/8G/Win10 1903+；Pad 仅支持安卓 11/12；<50 台单 AP、>50 台 AC+瘦 AP。
- **SDK 四件套**（`com.picoxr.businesssuite.clientsdk` 等）：
  - SDK-PC：C/C++ `PXREAClientSDK.dll`，JSON 通用指令集 + 回调枚举（设备发现/电量/画面监控/播控结果/自定义消息）；4.1.4 起画面监控支持多路、最高 25 路。
  - SDK-Unity：`PXRBusinessSuiteAPI` + `OnDeviceCmd` 事件 + `YuvTexture2D` 画面渲染。
  - SDK-PAD：AAR + `PbsBroadcastingHelper`，需 `com.picoxr.permission.BROADCASTING` 动态权限，`pre_resource/key-setting.txt` 写 `isServiceMode=1` 开服务模式。
  - SDK-HMD：头显端 AAR，`EAClientServiceManager` 双向 JSON 消息通道——**官方已有"控制端↔三方 apk"消息通路，我们自研通道的协议设计参照它**。
- **我们为什么不直接用**：套件是局域网单机工具，没有多租户、没有计费、没有云端、没有额度——但它验证了所有设备能力的可行性，是我们 M1 的功能对标。

### 2.4 企业串流（PCVR）

- v2.2 为当前版本（v2.1/v1.0 并存）；串流 SDK 提供头显端与 PC 端配对、画面传输能力。
- 串流模式下游戏跑在 PC 上——我们方案中"串流主机独立 PC + 伴生程序抓帧回传"的依据；另有 DP 直连方案文档（Streaming-DP）可作高性能备选。

### 2.5 MDM 官方云平台 —— 差异化定位

- PICO 官方 MDM 已有：设备管理、内容管理、团队管理、Wi-Fi 下发、视频加密、费用模式。
- **我们的差异点**：MDM 管"设备"，不管"营业"——没有启动次数计费、没有额度体系、没有运营方多租户分账、没有内容内嵌 SDK 深度控制。这正是自研的价值区间。

### 2.6 交付运维工具箱（企业设置板块）

- 设为主 Launcher（Set-As-Launcher-App）、自定义 Launcher 推荐位、开机自动投屏（Miracast）、在线/离线升级、Recovery 恢复出厂、adb 工具、日志抓取——交付和售后运维直接引用。

## 3. 关键约束与坑（设计时必须遵守）

1. 高风险接口声明后**不能上架 PICO 商店**——只能企业分发，需与 PICO 商务书面确认授权。
2. 画面监控官方上限 **25 路**——我们一期做 9 路宫格是保守可行值。
3. Pad 播控官方仅支持**安卓 11/12**——采购 Pad 时的硬性条件。
4. Device Owner 需要 **PUI 5.13.0+**——交付设备刷机基线。
5. 在线部署单包 **≤10G**、**5 台并行**——大内容包必须走我们本地服务局域网分发，不能依赖套件在线推送。
6. TobService 全系接口**仅企业版设备可用**——消费版 PICO 无法纳入管控。

## 6. 补遗：AAR 4.3.24 实物考古（M0-FIX-01，2026-10-15，已独立复核）

> 来源：Claude Code 按任务卡 M0-FIX-01 解压 `tobservicelib-4.3.24.aar` 考古（类清单 218 行 + javap 证据），Kimi 已从 PICO 官方 Maven 仓库重新下载同一 AAR 独立抽查复核一致。**以下以 AAR 为准，优先级高于文档记载。**

### 6.1 真实包结构（文档未记载，原推断 com.picoxr.* 全部错误）

| 类 | 真实全限定名 |
|---|---|
| 绑定入口 | `com.pvr.tobservice.ToBServiceHelper` |
| 绑定回调 | `ToBServiceHelper$BindCallBack`（单方法 `bindCallBack(Boolean)`，**C 大写**，不是 onBindSuccess/onBindFailed） |
| 原始 AIDL 接口 | `com.pvr.tobservice.interfaces.IToBService`（`getServiceBinder()` 的返回类型） |
| 扩展代理接口 | `com.pvr.tobservice.interfaces.IToBServiceProxy`（**extends IToBService**） |
| 代理实现 | `com.pvr.tobservice.impl.ToBServiceProxyImpl(IToBService)` |
| 回调 AIDL | `com.pvr.tobservice.interfaces.IIntCallback` / `IBoolCallback`（均含 `$Stub`） |
| 枚举 | `com.pvr.tobservice.enums.PBS_*Enum` |

**标准用法**：`proxy = ToBServiceProxyImpl(ToBServiceHelper.getInstance().getServiceBinder())`，之后 pbs* 方法与扩展方法全量可用。

### 6.2 与文档不一致（3 条，实锤）

1. 绑定回调：实为 `BindCallBack{bindCallBack(Boolean)}`（true=成功）。
2. `getServiceBinder()` 返回原始 `IToBService`，**不能**直接当 `IToBServiceProxy`，须经 `ToBServiceProxyImpl` 包装。
3. `appCopyrightVerify(String, Consumer<Integer>)`——第二参是 `java.util.function.Consumer`，**不是**文档另一处记载的 `IIntCallback`（歧义实锤；若真机抛 NoSuchMethodError 则为系统服务版本与 AAR 4.3.24 不齐，需问官方）。

### 6.3 枚举全量（javap 抄录，V2/V7 考古交付物提前到手）

- `PBS_DeviceControlEnum`：`DEVICE_CONTROL_REBOOT`、`DEVICE_CONTROL_SHUTDOWN`（关机有了，V6 可补测）
- `PBS_PackageControlEnum`：`PACKAGE_SILENCE_INSTALL`、`PACKAGE_SILENCE_UNINSTALL`

### 6.5 官方技术支持答复（2026-10-15，对接人渠道）

1. **setDeviceOwner 返回 2 的原因**：该接口属**功能授权项"允许设置 Device Owner"**，非默认开放，未授权返回 2（权限校验失败）；其他 TobService 接口不受影响。→ M0 V9 黄灯原因实锤，授权开通流程待对接人进一步确认（批量设备授权方式需问清）。
2. **Device Owner 设置方式**：无需出厂预装，官方支持两种——SDK 运行时 `setDeviceOwner(ComponentName)`（需授权）、或 `adb shell dpm set-device-owner`。
3. **录屏接口**：官方推荐 **SurfaceView**（`surfaceView.getHolder().getSurface()`）；TextureView 需等 SurfaceTexture 就绪并设置 buffer 尺寸，否则"调用受理但无画面"——与 M0 V5 实测现象及 M0-FIX-02 修复方向一致。
