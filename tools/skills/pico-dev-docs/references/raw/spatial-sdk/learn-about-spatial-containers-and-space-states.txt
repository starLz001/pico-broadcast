了解空间容器 & 空间状态
========================================
在 PICO OS 6 中，空间容器（Spatial Container）是用来承载和管理空间应用内容的核心组件。你可以把各种内容放入其中，比如传统的 2D 界面、3D 模型，以及各种可交互组件。不同的空间容器在展示方式和交互能力上各有特点，你可以根据应用场景选择最合适的容器，从而让用户以最自然、直观的方式与内容进行互动。
*空间容器
空间容器分为 WindowContainer 和 Stage 两大类。
*WindowContainer
*WindowContainer 是应用基本的承载容器，具有明确的空间边界。边界之内的内容由应用自身定义和控制，超出边界的内容会被自动裁切。一般情况下，当用户打开一个 WindowContainer 时，该容器会默认出现在用户前方约 1.75 米 的位置，其中心位置始终落在用户头戴设备当前朝向的方向上；也就是说，用户头部朝向哪里， WindowContainer 的中心就会出现在该方向上。
*WindowContainer 有两种类型，分别是以展示 2D 内容为主的 Planar 和以展示 3D 内容为主的 Volumetric。应用可以按需灵活地开启一个或多个 WindowContainer。
*Planar
*Planar 是一种厚度有限的、类似于 “平面面板” 的 WindowContainer。它主要用于承载传统 Android 开发中常见的 2D 界面，并可用于展示尺寸较小的 3D 对象。
*如果你习惯于传统 2D 应用的 UI 设计与开发，或计划迁移现有的移动端、桌面端应用至 PICO OS 6，那么 Planar 将是理想的起点。Planar 延续了 Jetpack Compose 的开发范式，并融合 PICO OS 6 的空间 UI 组件（Spatial UI），让经典的 2D 应用空间化。你只需专注于界面和功能本身，而复杂的空间交互逻辑与窗口管理则由 PICO OS 6 统一处理，大幅减少重复性工作。
* 
*Volumetric
*Volumetric 是另一种以窗口形式呈现内容的容器，可以被理解为尺寸可动态调整的 “长方体”。相比厚度有限的 Planar 容器，Volumetric 占据更大的空间体积，能够承载更大尺寸的 3D 物体，从而在有限范围内最大化用户的 3D 交互体验。
*Volumetric 主要用于融合 2D 与 3D 内容，支持基础的 3D 物体展示和交互操作。
* 
需要注意的是，如果 3D 内容超出了 WindowContainer 的边界，将会被裁剪。所以，如果你需要放置较大的 3D 模型，建议使用 Stage。
* 
*Stage
*Stage 可以被视为一块无边界限制的 “场地”，支持放置更多内容，包括 UI 组件、2D 布局、3D 模型等。
*如果你需要在空间中放置大范围内容，或需要更高的环境控制能力，可以使用 Stage。Stage 每次打开时，都会以用户头戴设备当下的位置和朝向完成一次空间对齐：其中心点位于用户脚下，并以当时的空间姿态作为坐标参考系，采用右手坐标系，其中 X 轴指向用户右侧，Y 轴指向正上方，Z 轴指向用户身后（与用户面朝方向相反）。
*在 Stage 中，3D 与 2D 内容的布局限制更少。你还可以申请更高等级的交互与感知权限，例如手势交互、空间锚点和平面检测，用于构建沉浸式或虚实融合的空间场景。
* 
*Stage 提供了多种样式，用于控制真实环境的视频透视（Video see-through, VST）与虚拟场景的融合方式，以及基于图像的环境光照（Image-based lighting, IBL）和虚拟实体的渲染行为。你可以通过 openStage() 函数的 style 参数来指定要使用的样式。
*
*空间状态
*空间应用所在的空间有两种状态：Shared Space 和 Full Space。
*
*空间状态会随着空间容器的打开与关闭自动切换。假设空间初始状态为 Shared Space，其状态切换规则如下：
*应用打开 Planar WindowContainer 或 Volumetric WindowContainer 时，空间状态保持为 Shared Space。此时当前空间中可以同时有多个应用运行。
*应用打开 Stage 时，空间状态切换为 Full Space。此时该应用完全占有当前空间，如果空间中同时有多个应用运行，其他应用的窗口会被隐藏到后台。
*应用关闭 Stage 后，空间状态会切回 Shared Space，此时当前空间又可以同时有多个应用运行。
*PICO OS 6 会根据不同的空间状态，动态采用针对性的性能优化策略：
* 在 Shared Space 状态下，系统对多任务运行场景进行了渲染层级的深度调优，通过任务优先级调度、资源动态分配与图层合成优化等机制，即使多个应用同时运行，也能确保画面流畅、操作响应及时，保障用户在多窗口环境下的使用体验。
* 在 Full Space 状态下，系统进一步强化渲染表现，重点优化全局光照、材质细节与交互延迟控制，即便在高复杂度的 3D 场景中，也能提供高保真、低延迟且稳定可靠的沉浸式体验。





内容裁剪会产生较高的性能开销，因此不建议你将物体默认摆放为部分超出边界区域的状态。



样式

描述

Automatic

Stage 样式由系统决定。当前，系统的默认设置为 Mixed 样式。

Mixed

虚拟实体始终被渲染，且基于图像的环境光照完全来自真实环境的视频透视。
*下图展示了 Mixed 样式下的场景。在这个示例中，一个虚拟的金属小球被天空球包裹。尽管天空球使用了“夜间美术馆”贴图并开启了基于图像的环境光照，但小球反射的仍是真实环境（卧室）的视频透视。这是因为 Mixed 模式下的环境光照完全来自真实房间的视频透视，而非夜间美术馆。
 


Progressive

允许你通过调节沉浸度从而改变真实环境的视频透视与虚拟实体的融合方式。你可以通过 Stage 的 immersion 参数设置沉浸度。沉浸度的取值范围为 0~100：
*immersion 为 0：体验接近 Mixed 样式，你仍然可以看到真实环境。但与 Mixed 样式不同的是，虚拟实体不被渲染。因此，金属球和夜间美术馆都会消失。
*immersion 大于 0 且小于 100：随着immersion数值提高：真实环境的渲染程度逐渐降低；虚拟实体渲染的程度逐渐提升。
*immersion 为 100：等同于 Full 样式。详情参阅 Full 样式的描述。
*下图展示了 Progressive 样式下 immersion 为 50 时的场景。在这个示例中，一个虚拟的金属小球被天空球包裹。天空球使用了“夜间美术馆”贴图并开启了基于图像的环境光照。你可以看到，金属球的反射效果是真实环境（卧室）的视频透视与夜间美术馆的混合。其中，金属球的正面是真实环境的视频透视，边缘和背面是美术馆。
* 
*

Full

虚拟实体始终被渲染，且基于图像的环境光照完全来自虚拟场景。因此，如果你不设置虚拟场景，应用将因缺少光照而显示为纯黑背景。
*下图展示了 Full 样式下的场景。在这个示例中，一个虚拟的金属小球被天空球包裹。天空球使用了“夜间美术馆”贴图并开启了基于图像的环境光照。你可以看到，金属球完全反射虚拟的夜间美术馆。真实环境（卧室）被完全屏蔽。
 




空间状态

描述

Shared Space

*在 Shared Space 状态下，一个空间可被多个应用同时占用，支持多应用协作与内容融合。
*Shared Space 仅支持 Planar WindowContainer 和 Volumetric WindowContainer。
* 

Full Space

在 Full Space 状态下，一个空间仅由单个应用独占。当一个应用打开 Stage 时，系统会将空间切换至 Full Space 状态，此时该应用完全占有当前空间，其他应用的窗口会被隐藏到后台。
*在 Full Space 中，独占空间的应用可以在空间内同时放置一个 Stage 和多个 WindowContainer。关闭 Stage 后，空间会自动切换至 Shared Space 状态。
*Full Space 支持同一个应用的 Stage，Planar WindowContainer 和 Volumetric WindowContainer。
*
