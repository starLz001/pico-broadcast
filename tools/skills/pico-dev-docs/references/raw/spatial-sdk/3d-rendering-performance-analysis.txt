渲染流程
========================================
*空间应用是在 PICO OS 6 上运行的一种全新应用形态。本文介绍其在统一渲染（Unified Rendering）框架下的核心渲染流程，并结合该框架的特点，提供性能分析与优化的建议。
PICO OS 6 的统一渲染流程包含两大核心角色：
*PICO 空间引擎（PICO Spatial Engine）：为所有空间应用提供统一渲染服务。它负责处理并合成来自多个应用的内容，最终将渲染结果提交给合成器。
*合成器（Compositor）：与 V-Sync (垂直同步) 信号对齐，负责将内容最终显示在屏幕上。它和 PICO 空间引擎共同构成了空间应用的渲染底层。
 
*帧生命周期
*PICO 空间引擎旨在通过封装标准化的渲染能力来降低开发门槛，使开发者能更专注于业务逻辑与交互体验的创新。尽管如此，为保障应用的流畅运行，你在构建渲染任务时，仍需充分考虑系统资源的合理分配，避免因单帧任务过于复杂而影响整体性能。
理解空间应用单帧画面的生命周期，有助于你更高效地利用统一渲染能力，并在出现性能问题时快速定位。空间应用一帧的生命周期分为以下四个阶段：
 
*渲染任务的创建与提交：
*此阶段在你的空间应用进程中执行。你需要根据用户的交互和业务逻辑，更新并创建 2D/3D 渲染任务，然后将其提交。具体流程如下：
*2D 渲染：你可以使用 UI 组件和布局组件构建用户界面。这些组件将遵循“Compose 重组 → EC 数据转换 → 数据提交”的流程，最终以实体-组件（Entity-Component, EC）数据的形式提交给 PICO 空间引擎。
*3D 渲染：你可以通过 ModelComponent、ParticleComponent 等组件来设计 3D 场景。这些组件最终同样会以 EC 数据的形式提交给 PICO 空间引擎。
 
* 
*一帧的渲染与提交：
*此阶段在 PICO 空间引擎进程中执行。在每帧开始时，引擎会获取所有空间应用提交的渲染任务，经过统一渲染与合成，生成该帧的最终图像，并提交给合成器。
*该阶段可分为以下两个子阶段：
*CPU 阶段：组织并提交绘制命令
*PICO 空间引擎的 CPU 会接收并处理所有应用提交的 2D 和 3D 渲染任务。
*处理渲染任务：整理 2D/3D 渲染任务，生成 GPU 可执行的绘制命令列表，并处理模型变换、光照计算等复杂几何运算。
*准备渲染资源：加载并准备渲染所需的纹理、材质、Shader 等资源，确保 GPU 执行渲染时所有资源均已就绪。
*GPU 阶段：根据绘制命令完成渲染
*尽管 CPU 和 GPU 异步工作，但基于 PICO Space Pro 设备的硬件特性，GPU 会在收集完当前帧的所有绘制命令后，才开始执行该帧的最终渲染。
*2D 统一渲染：GPU 执行 2D UI 的渲染，包括纹理采样、像素着色等操作。2D 渲染的 GPU 负载通常低于 3D 渲染，但包含毛玻璃、半透明等特效时会显著增加 GPU 负载。
*3D 统一渲染：GPU 执行复杂的 3D 渲染管线，包括顶点着色、光栅化、像素着色、光照计算和阴影生成等。GPU 负载主要受模型复杂度、三角面数量、纹理大小、光源数量等因素影响。
*同步机制：当 GPU 完成该帧的所有 2D/3D 渲染后，会通过同步机制通知合成器（Compositor）该帧已可使用，从而完成提交。CPU 和 GPU 的性能紧密相关：如果 CPU 组织绘制命令耗时过长，会导致 GPU 空闲等待；反之，如果 GPU 负载过重，也会影响下一帧的 CPU 提交。
* 
*合成器获取这一帧：
*合成器会在预期的时刻，尝试获取 PICO 空间引擎提交的最新帧。如果未能按时获取（例如，由于引擎处理超时），合成器会复用前一帧的画面进行显示。因此，为确保流畅的视觉体验（即应用的显示帧率与硬件刷新率保持一致），PICO 空间引擎必须在规定时间内完成每帧的提交。
* 
*合成器完成内容的最终上屏显示：
*图像帧抵达合成器后，还需经过图层合成、VR 畸变校正等一系列步骤，最终才会在正确的时间显示在屏幕上。这些步骤均由系统自动完成，无需额外关注。


在统一渲染架构下，应用进程本身不执行 UI 的 GPU 绘制，而是将渲染任务提交给 PICO 空间引擎来统一完成。
