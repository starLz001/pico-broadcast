空间锚点
========================================
空间锚点技术可以将虚拟环境中的位置与真实世界中的位置进行锚定。放置空间锚点并将其持久化至设备磁盘中后，用户再次走到放置锚点的位置时，系统可以找回该锚点并返回给应用。
* 
*使用场景
空间锚点的部分使用场景如下：
*虚拟物体放置和交互
*将应用中的角色、道具等虚拟物体放置在玩家周围的实际环境中，并精准地记忆放置位置。后续玩家回到场景中后，应用能够展现先前放置的物体。
*环境感知和游戏关卡设计
*利用空间锚点技术，应用可以感知玩家所处的真实环境信息。根据环境特征自动生成或调整游戏关卡，使应用内容与现实场景更好地融合。
*基本概念
*
*空间锚点的生命周期
为了在真实世界中放置虚拟物体，首先要创建一个空间锚点。紧接着，你需要将锚点持久化至设备的本地磁盘，以便应用可以查询并加载锚点。用户删除虚拟物体后，及时销毁或去持久化相应的锚点，以释放资源。
* 
*创建锚点
*在应用的内存中创建锚点。请求会返回所创建锚点的 UUID 和 Handle，用于在后续操作中指定锚点。
*持久化锚点
*将锚点持久化至设备的本地磁盘。持久化锚点后，使用同一设备多次进入相同的空间后，可以找回已经保存的锚点。
*查询并加载锚点
*用户在场景内移动时，应用会查询并加载先前持久化的锚点，使其在场景中显现出来。
*销毁或去持久化锚点（可选）
*从应用内存中销毁锚点后，应用依然可以从设备本地磁盘中加载该锚点。将该锚点从设备本地磁盘中去持久化后，便无法被查询和加载。
*开发环境
*PICO 设备型号：PICO 4 Ultra 系列
*PICO 设备系统版本：5.11.0 及以上
*前提条件
*已为场景添加 XR Origin 对象。
*已为应用开启视频透视能力。详细说明参考《透视》。
*开启空间锚点能力
*前往 Edit > Project Settings > XR Plug-in Management > OpenXR > OpenXR Feature Groups > All Features，然后勾选 PICO Spatial Anchor 选框，为应用启用空间锚点能力。此后，你可以调用空间锚点相关接口，在应用内实现空间锚点功能。
 
*关于 Anchor Subsystem：
*在项目内添加 5.1.2 及更高版本的 AR Foundation 插件后，若你不想使用 AR Founfation 插件提供的方式来开发空间锚点功能，而想通过 PICO SDK 提供的接口进行开发，则可以在 PICO Spatial Anchor 窗口中取消勾选 Is Anchor Subsystem 选框。
 
*开始/停止空间锚点功能
调用其他空间锚点接口进行相关操作前，需要调用 StartSenseDataProvider 接口，开始空间锚点功能。操作完成后，调用 StopSenseDataProvider 接口，停止空间锚点功能。两个接口中都需要指定空间锚点数据 Provider（SpatialAnchor）。
 
*获取空间锚点数据 Provider 的状态 
此为非必须流程。若你在调用 StartSenseDataProvider 接口后没有暂存 Provider 的状态，便可以调用 GetSenseDataProviderState 接口来判断 Provider 是否启动成功。
 
*创建空间锚点
调用 CreateSpatialAnchorAsync 接口，在应用的内存中创建锚点。API 请求会返回所创建锚点的 UUID 和 Handle。
创建锚点后，若不持久化该锚点，退出应用后该锚点便会被销毁。若希望应用始终能够找回已创建的锚点，需要将锚点持久化至 PICO 设备的本地磁盘中。
 
建议在应用的设计上满足锚点和用户间的交互体验，例如，尽量在用户头戴 3 米范围以内放置锚点。放置锚点后，如果想要精准地找回该锚点，需要用户在该锚点附近多看多走动。
放置锚点后，可以在以用户为中心 3 米范围内进行观察和建图。锚点的找回范围与用户在放置锚点后观察的范围相关，半径最大不会超过 5 米。超过 5 米的位置如果没有其他锚点存在，则可能找不回锚点。
*持久化空间锚点
调用 PersistSpatialAnchorAsync 接口，将空间锚点持久化至 PICO 设备的本地磁盘。持久化锚点后，使用同一设备多次进入相同的空间后，可以找回已经保存的锚点。你可以长久地使用该锚点，也可以在该锚点被销毁后继续调用接口查询和加载该锚点。
 
*加载空间锚点
* 
成功创建空间锚点后，每个锚点都会获得一个唯一的 UUID。你可以在 QuerySpatialAnchorAsync 接口中传入 UUID 列表，从设备本地磁盘或应用内存中加载指定锚点。调用 QuerySpatialAnchorAsync 前，需要先调用 GetAnchorUuid 获取锚点的 UUID。若不传入任何 UUID，则返回所有可用的锚点。
 
如果用户之前放置过锚点，但现在无法查询到该锚点的相关信息，你可以引导用户返回上次放置锚点的位置。如果用户不需要找回之前的锚点，或者想换个地方放置新的锚点，你可以让用户重新放置交互物体或标定当前空间，在新地点体验应用。
*获取空间锚点的 UUID
调用 GetAnchorUuid 接口，获取锚点的 UUID。你可以通过 UUID 加载指定锚点。
 
*获取空间锚点的实时位置
调用 LocateAnchor 接口让你的应用获取锚点的实时位置，目的是为了保证将锚点锚定在现实世界中的固定位置。若不获取，当用户在场景内移动时，锚点的位置可能会发生偏移。
此接口的调用频率可根据实际需求自行决定，建议 1 秒左右调用一次，最高支持每帧调用。
 
*销毁空间锚点
调用 DestroyAnchor 接口，将锚点从应用内存中销毁。若创建锚点之后立刻销毁，则无法找回该锚点；若创建锚点后将该锚点持久化至设备本地磁盘，销毁锚点后，用户下一次打开应用时仍旧可以查询和加载该锚点。
 
*去持久化空间锚点
调用 UnPersistSpatialAnchorAsync 接口，将锚点从设备本地磁盘中去持久化。去持久化后的锚点将无法被查询和加载。用户删除虚拟物体后，建议及时去持久化相关联的锚点。也建议去持久化长久不用的锚点，释放系统资源。
 
应用内存和设备本地磁盘中的锚点通过 anchorHandle 进行关联，即 anchorHandle 类似于对保存于磁盘上的锚点的引用。当你首先调用 DestroyAnchor 时，anchorHandle 会被删除，你将无法继续引用磁盘上的锚点。然后，当你调用 UnPersistSpatialAnchorAsync 去持久化具体的锚点时，系统将无法找到该锚点。在这种情况下，请先调用 UnPersistSpatialAnchorAsync，然后再调用 DestroyAnchor。
*发现新的空间锚点
*监听 OpenXRExtensions.SpatialAnchorDataUpdated 事件。接收到此事件则说明发现了新的空间锚点数据。
 
*现实环境考量
综合考虑以下环境因素，有助于在应用内提供更好的空间锚点体验。
*在使用空间锚点技术时，需特别注意环境要求。其中，诸如白墙、重复图案等环境因素可能会影响锚点精度。为确保空间锚点的精准度和稳定性，在实际应用场景中，应尽量避免或减少此类环境因素的干扰。
*光照的强度和方向会影响传感器的检测精度。强光或阴暗的环境可能会导致跟踪失败。最佳的光照条件是均匀且适度的环境光。
*若场景中的变化或者动态物体较多，可能会影响锚点的使用。
*用户的移动速度和移动方式会影响跟踪的稳定性。缓慢、平稳的移动有利于保持良好的定位精度。

名称

说明

UUID

通用唯一识别码，为锚点的唯一标识，在创建锚点时分配，可用于加载指定锚点。

Handle

通过 Handle 可以将应用内存和本地磁盘中的锚点进行关联。在销毁、持久化、去持久化锚点，以及获取锚点的 UUID 和实时位置时，需要通过 Handle 指定锚点。Handle 不是永久不变的，应用重启后 Handle 就会发生变更。
