房间&匹配
========================================
房间&匹配模块提供了联网游戏、在线匹配、房间管理、房间内用户互动等能力，主要包括房间功能、匹配功能、和消息收发功能。
*应用场景
房间&匹配模块主要有以下应用场景：
*实时对战
*玩家匹配后，可加入同一房间，进行实时游戏对战。
*实时交流
*支持消息收发功能。同一房间内玩家可互相发送和接收消息，进行实时交流。
*基本概念

*功能说明
*房间
PICO 提供的房间默认有以下设置： 
*房间所有权转让：房主离开房间后，房间的所有权将自动转移给在房间中停留时间最长的用户。 
*销毁房间：当所有人都离开房间时，房间会被销毁。 
*房间内接收或发送消息：玩家可向房间内其他玩家发送消息，接收来自房间内其他玩家的消息。 
你可调用房间相关接口创建房间、设置房间名称、设置房间密码、获取房间信息、修改房间数据、转移房主、离开房间等。

*匹配
匹配功能提供加入匹配、浏览符合匹配条件的房间、创建匹配房间、通知比赛开始等能力。
*匹配流程
一个基本的匹配流程如下：
*开发者创建一个或多个匹配池，并为匹配池配置匹配条件。
*开发者将匹配池与应用关联。
*收到玩家的匹配请求后，系统将玩家加入匹配池，并将其他满足相同条件的玩家加入到同一个匹配池。
*匹配成功后，系统通知相关玩家。
*被匹配的玩家进入同一房间，开始游戏。
 
*匹配模式
*你可通过匹配池配置来实现三种匹配模式：基本匹配、高级匹配、浏览匹配。具体说明和配置参考下文 ”创建匹配池“ 部分。

*注意事项
*初始化结果处理机制
若开发者在游戏模块未进行初始化或初始化完成后发生错误时，使用房间&匹配模块，插件会进行一些默认处理。处理过程如下：
*判断 InitSuccess 返回值。
*插件内部会维护一个“是否可使用该模块的状态” - InitSuccess，InitSuccess是一个 bool 类型的变量：
*当 InitSuccess = true 时，表示“初始化状态为成功且网络状态正常”，此时开发者可以进行游戏模块各项接口的调用；
*否则，调用接口将报错，错误信息为“Error: InitSuccess is false”。
* 
*处理初始化失败结果。
*若初始化失败，插件内部会重新尝试初始化直至初始化成功。由于初始化需要先获取 token，获取 token 失败也算作初始化失败，获取 token 的失败将不会再尝试重新初始化，需重新启动 demo 才会重新尝试；或者开发者可以使用派生类指针自定义这里的处理。
*若初始化成功，用户可能会遭遇网络断连与重连，此时 Connection 的状态为 Lost，InitState 为 false，开始进行自动重连；当再次收到 Connction 状态为 Resume 时，将恢复 InitState 为 true。
*其他状况处理。
*当用户被服务器踢下线或当前使用账号被其他设备登录而被迫下线时：
*插件首先将 InitState 设置为 false，重置房间状态和匹配状态。
*如果开发者设置了自定义的回调函数，将执行用户的自定义回调函数；如果开发者使用接口清除设置的回调函数，则弹出提示窗，选择 OK 则重新初始化（将另一个登录该账号的设备顶号），选择 Cancel 将不做任何处理，如下图所示：

*应用程序长时间在后台运行将导致消息丢失

                        {
                                UE_LOG_ONLINE(Display, TEXT("PPF_GAME FOnlineSessionPico::OnNetNotificationConnection click ok button."));
                                Initialize();
                        }
                        else
                        {
                                UE_LOG_ONLINE(Display, TEXT("PPF_GAME FOnlineSessionPico::OnNetNotificationConnection click cancel button."));
                        }
                }
        }
        else
        {
                SetInitState(false);
                if (InProgressMatchmakingSearch.IsValid() && InProgressMatchmakingSearch->SearchState == EOnlineAsyncTaskState::InProgress)
                { // in matchmaking
                        OnForcedCancelMatchmaking();
                }
                else
                { // in room
                        OnForcedLeaveRoom();
                }
                GameConnectionCallback.Broadcast((int)ConnectionResult, false);
                Uninitialize();
                Initialize();
        }
#endif
}

是否管理房间
*选择 是 后，可配置右侧四个字段


谁能创建房间


设置可以创建房间的对象。选项如下，支持多选：
*用户：允许用户创建私人房间
*匹配服务：允许匹配服务创建匹配房间
你至少需选择一个选项，否则将无法创建任何房间来进行玩家间匹配。如果同时勾选两个选项，则同一个匹配池中同时存在私人房间和匹配房间。在这种情况下，发送匹配请求的用户有可能会随机加入其他玩家创建的私人房间或匹配服务创建的匹配房间。



是否允许非匹配用户加入匹配房间

是否允许非匹配服务匹配的用户加入房间，即是否允许玩家主动浏览可加入房间，并选择加入。
若开启，则其他用户也可以加入房间，例如，房间成员可邀请好友加入。
若关闭，则只有通过匹配服务成功匹配的用户才可加入房间。



是否允许匹配服务多次匹配到这个房间

匹配完成后，是否允许继续匹配其它玩家中途加入房间。
若开启，匹配服务可能多次匹配到同一房间，比如将匹配成功的用户有序放入同一房间。
若关闭，则一旦有用户匹配成功，相应的房间将被移出匹配队列。



房主自动转移

若开启，则当房主离开或断线时，加入该房间时间最长的用户将自动成为新房主。
若关闭，则房主离开后，该房间房主为空。

匹配度阈值




可匹配成功的最小匹配度，取值范围为 0 至 1，1 表示完美匹配。匹配度大于等于阈值才能匹配成功。
提示：若两个用户之间的匹配度阈值未达到 1，则通过该值计算需等待的时间。等待时长的计算公式为：(1-匹配值)/(1-匹配度阈值) * rampdown。因此，匹配值越接近 1，等待时间越短；匹配值越接近匹配度阈值，等待时间越长，最多等待 rampdown 时长。

匹配保留时间（单位：秒）



表示用户被匹配到一个房间后，为其保留多少时间进入房间，超时后释放该位置。

建议冷却时间（单位：秒）



表示用户被匹配到一个房间却因超时被释放位置，冷却多少时间后才可再次加入匹配。

特别设置:
*是否管理房间 = 是
*谁能创建房间 = 用户 / 用户 & 匹配服务

浏览模式适用于玩家创建房间以及主动选择加入其他玩家创建的房间的场景。该模式下的房间都由玩家自行创建，并且系统不执行自动匹配加入，只返回符合条件的房间列表，供玩家选择加入。

说明

Data Key

自定义数据的唯一标识，例如：Level。

数据类型

包括：

默认值

自定义数据的默认值。该默认值为兜底取值。

只有添加自定义数据后，才可以添加匹配查询。



参数

说明

Query Key

匹配查询的唯一标识。

表达式权重

表达式的重要性等级，包括：必要、高、中、低，重要性等级依次递减。重要性越高，计算双方匹配度时的权重因子越小，其中 必要 = 0、高 = 0.55、中 = 0.75、低 = 0.9。
若双方条件无法满足 必要 表达式，则必定匹配失败。若双方条件满足 必要 表达式，但无法满足其余等级的表达式，则匹配结果根据所有表达式因子的乘积是否大于匹配度阈值决定。

表达式

表达式用于计算用户之间的匹配值。同一查询可由多个表达式构成，你可以给每个表达式设置权重。系统将按权重组合这些表达式的结果，得到最终的匹配值。
每个表达式的结果为布尔值：true 或 false：
*若结果为 true，该表达式产生因子 1。
*若结果为 false，该表达式产生一个小于 1 的因子（expression_val）。表达式的重要程度越高，则结果为 false 时产生的因子值越小。最终匹配值为所有所有表达式因子的乘积，即：最终匹配值 = expression_val_1 * expression_val_2 * ...* expression_val_n。
若 A 和 B 参与匹配，系统会分别以 A 指定的表达式和 B 指定的表达式计算出 匹配值 A 和 匹配值 B。其中，较小的匹配值将作为最终的匹配值。若匹配值大于匹配度阈值，则立刻匹配，否则需等待一定时间。

void UPicoGameInstance::CreateSession(const FString& Keys, const FString& Values, bool bShouldAdvertise, bool bAllowJoinViaPresenceFriendsOnly, bool bAllowInvites, bool bAllowJoinViaPresence, int NumPublicConnections) {
    if (!GameInterface.IsValid()) {
        return;
    }
    
    if (!OnCreateSessionCompleteDelegate.IsBound()) {
        OnCreateSessionCompleteDelegate = FOnCreateSessionCompleteDelegate::CreateUObject(
            this, &UPicoGameInstance::OnCreateSessionComplete);
        GameInterface->AddOnCreateSessionCompleteDelegate_Handle(
            OnCreateSessionCompleteDelegate);
    }

    TSharedPtr<class FOnlineSessionSettings> SessionSettings = MakeShareable(new FOnlineSessionSettings());
    SessionSettings->NumPublicConnections = NumPublicConnections;
    SessionSettings->bShouldAdvertise = bShouldAdvertise;
    SessionSettings->bAllowJoinViaPresenceFriendsOnly = bAllowJoinViaPresenceFriendsOnly;
    SessionSettings->bAllowInvites = bAllowInvites;
    SessionSettings->bAllowJoinViaPresence = bAllowJoinViaPresence;
    TArray<FString> KeyArr, ValueArr;
    Keys.ParseIntoArray(KeyArr, TEXT(","), true);
    Values.ParseIntoArray(ValueArr, TEXT(","), true);
    if (ValueArr.Num() != KeyArr.Num())
    {
        UE_LOG_ONLINE(Error, TEXT("PPF_GAME UPicoGameInstance::CreateSession keys count != values count"));
        return;
    }
    for (int i = 0; i < KeyArr.Num(); i++)
    {
        SessionSettings->Set(FName(KeyArr[i]), ValueArr[i], EOnlineDataAdvertisementType::ViaOnlineService);
    }
    GameInterface->CreateSession(/* Hosting Player Num/ 0, TEXT("Game"), SessionSettings);
}
