房间&匹配
========================================
“房间&匹配” 服务为开发者提供了联网游戏、在线匹配、房间管理、房间内用户互动等能力，主要包括房间功能、匹配功能和消息收发功能。
*应用场景
“房间&匹配” 服务的主要应用场景如下：
*实时对战
*支持匹配和房间功能，玩家匹配后可加入同一房间，进行实时游戏对战。
*实时交流
*支持消息收发功能。同一房间内玩家可发送和接收消息，进行实时交流。
*基本概念
“房间&匹配” 服务涉及的基本概念如下：
*
*功能详解
*房间相关
房间功能提供创建房间，获取房间信息，修改房间数据，转移房主，离开房间等能力。
*房间类型
“房间”功能支持创建四种类型的房间：私人房间、命名房间、系统房间、匹配房间。
*
*房间内消息通知
房间功能支持在游戏循环中添加监听器以获取通知。例如：你可以调用 Notification_Room_RoomUpdate 接口来允许用户获取房间更新相关通知，该通知类型的回调函数设置如下：
 
*匹配相关
匹配功能提供加入匹配，浏览符合匹配条件的房间，创建匹配房间，通知比赛开始等能力。
*匹配流程
一个基本的匹配流程如下：
*创建一个或多个匹配池，并为匹配池配置匹配条件。
*将匹配池与应用关联。
*收到用户的匹配请求后，系统将用户加入匹配池，并将其他满足相同条件的用户加入到同一个匹配池。
*匹配成功后，系统通知相关用户。
*匹配成功的用户进入同一房间，开始游戏。
 
*匹配模式
*你可通过匹配池配置来实现三种匹配模式：基本匹配、高级匹配、浏览匹配。具体说明和配置参考下文 ”创建匹配池“ 部分。
*消息收发相关
消息收发功能支持以下能力，消息内容与格式由你自行定义：
*自定义房间内消息收发
*同房间内用户互发消息
*广播消息给同房间内所有用户
*重要提示
*使用游戏模块时，你需要监听网络事件。当用户断网和重连时，你会收到以下事件推送：
* 
*Lost 事件明用户断网，此时，你需要暂停向客户端侧发送请求。Resumed 表示用户网络重连成功。建议你在游戏画面中通过 “转圈图标” 或其他合理方式提示用户 “重连中” 状态。
*若将应用切换到后台，popMessage 接口会被暂停使用，导致服务器无法收到应用的心跳。若心跳断连过久，会导致应用和服务器之间的连接断开，断连期间的消息会丢失。重新将应用切换到前台后，应用和服务器之间会进行重连。

概念
说明
匹配池
匹配池由开发者创建，用于匹配玩家。开发者可为匹配池配置匹配条件，使匹配结果更符合预期。
房间
房间支持玩家或系统创建。玩家匹配后将加入同一房间，进行游戏。


类型
说明
私人房间（private room）
私人房间由用户创建。相关说明如下：
*你可以调用 RoomService.Get() 接口并通过指定 roomID 参数来获取指定房间的信息，然后展示给用户。
*你可以调用 RoomService.UpdateMembershipLockStatus() 接口来允许房主锁定房间。锁定房间后，新用户将无法加入房间。对于房间锁定前已在房间内的用户，退出房间后可重新加入。
*你可以调用 RoomService.CreateAndJoinPrivate2() 接口来允许用户创建并加入房间，同时成为房间的所有者。接口包含 joinPolicy 和 maxUsers 参数。joinPolicy 参数定义谁可以加入房间；maxUsers 参数指定房间的最大用户数。最大值为 100。
*你可以调用相关接口来允许房主踢人（RoomService.KickUser），更新房间元数据（RoomService.UpdateDataStore），更新房间加入策略（RoomService.UpdatePrivateRoomJoinPolicy），锁定房间的会员资格（RoomService.UpdateMembershipLockStatus），设置或更改房间描述 （RoomService.etDescription）。
*房间内的用户可以得到房间事件通知（例如：用户进入房间、用户离开房间），向房间内的其它用户发送消息，接收来自房间内其他用户的消息
*你可以调用 RoomService.Leave() 接口来允许玩家离开房间。
*房主离开房间后，房间的所有权将自动转移给在房间里时间最长的用户。你可以调用 RoomService.UpdateOwner 接口来允许房主手动转移房间所有权。
*当所有人都离开房间时，房间会被销毁。
命名房间（named room）

命名房间由玩家创建，并设置房间名称。相关函数如下：
*RoomService.JoinOrCreateNamedRoom：加入或创建命名房间。
*RoomService.GetCreateNamedRoomOptions：获取加入或创建明明房间的配置项。
*RoomService.GetNamedRooms：获取命名房间列表。

系统房间（moderated room）
系统房间由游戏服务器创建，全员可见。你可以通过 Restful API 创建和管理房间的生命周期。用户可以使用自己的服务器，通过 Restful API 与 PICO 的房间服务交互。
匹配房间（matchmaking room）

匹配房间由系统创建。创建后，随机选择房间中的一位用户成为房主。相关说明如下：
*你需要在 PICO 开发者平台上创建并配置匹配池，用于玩家间匹配。
*你可以调用 Enqueue2 接口来允许用户加入匹配。用户可设置自定义数据中指定的字段以及选定的查询（Query）来提升匹配准确度。
*你可以调用 MatchmakingCancel2 接口来允许用户在任意时刻退出匹配。
*匹配成功时，用户会收到来自服务器的 Notification_Matchmaking_MatchFound 通知。你需要从通知中提取房间号，然后调用 JoinRoom2 接口将用户加入房间。
*房间内的用户可以得到房间事件通知（例如：玩家进入房间、玩家离开房间），向房间内的其他用户发送消息，接收来自房间内其他用户的消息。

public static void SetUpdateNotificationCallback(Message<Room>.Handler handler)

*匹配结果由匹配值（matchmaking value，match_val）决定。匹配值范围为 0 至 1，值越高，用户间的匹配度越高。在确定匹配值时，系统会参考用户之间的技能水平和其他相关数据。当匹配值超过预设的最小匹配阈值（matchbias）时，认为可以匹配。用户在匹配池中的等待时间越长，最小匹配阈值越低，越容易被匹配。
*对于十分复杂的匹配场景，除了系统自动匹配，你还可以调用 RoomService.CreateAndJoinPrivate2() 和 Browse2 接口来允许用户创建并加入房间或浏览已创建的房间。

void OnGameConnectionEvent(Message<GameConnectionEvent> msg)
{
    var state = msg.Data;
    LogHelper.LogInfo(TAG, $$"OnGameConnectionEvent: {state}");
    if (state == GameConnectionEvent.Connected)
    {
        LogHelper.LogInfo(TAG, "GameConnection: success！");
    }
    else if (state == GameConnectionEvent.Closed)
    {
        Uninitialize();
        LogHelper.LogInfo(TAG, "GameConnection: fail！Please re-initialize！");
    }
    else if (state == GameConnectionEvent.GameLogicError)
    {
        Uninitialize();
        LogHelper.LogInfo(TAG, "GameConnection: fail！After successful reconnection, the logic state is found to be wrong，Please re-initialize！");
    }
    else if (state == GameConnectionEvent.Lost)
    {
        LogHelper.LogInfo(TAG, "GameConnection: Reconnecting, please wait！");
    }
    else if (state == GameConnectionEvent.Resumed)
    {
        LogHelper.LogInfo(TAG, "GameConnection: successful reconnection！");
    }
    else if (state == GameConnectionEvent.KickedByRelogin)
    {
        Uninitialize();
        LogHelper.LogInfo(TAG, "GameConnection: Repeat login! Please reinitialize！");
    }
    else if (state == GameConnectionEvent.KickedByGameServer)
    {
        Uninitialize();
        LogHelper.LogInfo(TAG, "GameConnection: Server kicks people! Please reinitialize！");
    }
    else
    {
        LogHelper.LogInfo(TAG, "GameConnection: unknown error！");
    }
}

若人数在 推荐最少用户数 和 推荐最多用户数 之间，立刻匹配成功；若人数不在推荐区间内，但在 最少用户数 与 最多用户数 之间时，则等待一定时间；若等待过后仍无法达到期望人数，则匹配成功。

是否管理房间
*选择 是 后，可配置右侧四个字段


谁能创建房间


设置可以创建房间的对象。选项如下，支持多选：
*用户：允许用户创建私人房间
*匹配服务：允许匹配服务创建匹配房间
你至少需选择一个选项，否则将无法创建任何房间来进行玩家间匹配。如果同时勾选两个选项，则同一个匹配池中同时存在私人房间和匹配房间。在这种情况下，发送匹配请求的用户有可能会随机加入其他玩家创建的私人房间或匹配服务创建的匹配房间。



是否允许非匹配用户加入匹配房间

是否允许非匹配服务匹配的用户加入房间，即是否允许玩家主动浏览可加入房间，并选择加入。
若开启，则其他用户也可以加入房间，例如，房间成员可邀请好友加入。
若关闭，则只有通过匹配服务成功匹配的用户才可加入房间。



是否允许匹配服务多次匹配到这个房间

匹配完成后，是否允许继续匹配其它玩家中途加入房间。
若开启，匹配服务可能多次匹配到同一房间，比如将匹配成功的用户有序放入同一房间。
若关闭，则一旦有用户匹配成功，相应的房间将被移出匹配队列。



房主自动转移

若开启，则当房主离开或断线时，加入该房间时间最长的用户将自动成为新房主。
若关闭，则房主离开后，该房间房主为空。

匹配度阈值




可匹配成功的最小匹配度，取值范围为 0 至 1，1 表示完美匹配。匹配度大于等于阈值才能匹配成功。
提示：若两个用户之间的匹配度阈值未达到 1，则通过该值计算需等待的时间。等待时长的计算公式为：(1-匹配值)/(1-匹配度阈值) * rampdown。因此，匹配值越接近 1，等待时间越短；匹配值越接近匹配度阈值，等待时间越长，最多等待 rampdown 时长。

匹配保留时间（单位：秒）



表示用户被匹配到一个房间后，为其保留多少时间进入房间，超时后释放该位置。

建议冷却时间（单位：秒）



表示用户被匹配到一个房间却因超时被释放位置，冷却多少时间后才可再次加入匹配。

基本匹配

基本匹配模式下，所有玩家在同一匹配池中进行匹配，匹配完成时创建房间，后续不会再匹配其他玩家进入房间，也不允许其他玩家中途加入。所有玩家离开后，房间销毁。
开发者工作
*提供给玩家 '自动搜索匹配' 的入口与选项，包括可用匹配池，可用表达式，相关条件字段设置。
*可通过调用 RoomService.Join2 接口来允许玩家在收到匹配成功通知时进入房间。
*可通过调用 RoomService.UpdateDataStore 接口来允许玩家设置和读取房间逻辑相关数据（例如：游戏关卡，游戏当前进度等）。
玩家体验
*基本匹配模式下，玩家无法创建房间，只能通过系统自动匹配进入房间。
*允许玩家选择比赛类型（即：功能内部逻辑中的匹配池）。
*允许玩家设置搜索选项，进行自动搜索匹配（即：功能内部逻辑中的表达式选择和 datasetting 字段设置），例如：要求与自己等级相近的玩家一起玩某特定副本。

高级匹配

特别设置:
*是否管理房间 = 是
*谁能创建房间 = 用户 | 匹配服务 | 用户 & 匹配服务
*是否允许非匹配用户加入匹配房间 = 关闭
*是否允许匹配服务多次匹配到这个房间：根据是否允许玩家中途加入来设置


高级匹配模式允许玩家直接自行创建房间，并等待其他符合条件的玩家通过系统匹配加入。可以通过匹配池高级配置来满足更丰富的匹配需求场景。
开发者工作
*为玩家提供 '自动搜索匹配' 选项。玩家在匹配成功时进入房间。
*在允许玩家创建房间的情况下，为玩家提供创建房间相关选项，包括可用匹配池以及条件字段设置。
*调用 NetworkService.SendPacket，允许玩家向房间内的指定玩家发送消息。
*调用 NetworkService.SendPacketToCurrentRoom，允许玩家向房间内的所有其他玩家发送消息。
*调用 NetworkService.ReadPacket，允许房间内的玩家读取消息。
玩家体验
*玩家可设置搜索条件，进行自动搜索匹配。
*在允许玩家创建房间的情况下，玩家可设置房间创建选项，创建匹配房间。
*根据 是否允许匹配服务多次匹配到这个房间 的值，玩家有可能加入游戏正在进行中的房间。

浏览模式

特别设置:
*是否管理房间 = 是
*谁能创建房间 = 用户 | 用户 & 匹配服务
*是否允许非匹配用户加入匹配房间 = 开启
*是否允许匹配服务多次匹配到这个房间：根据是否允许玩家中途加入来设置


浏览模式适用于玩家创建房间以及主动选择加入其他玩家创建的房间的场景。该模式下的房间都由玩家自行创建，并且系统不执行自动匹配加入，只返回符合条件的房间列表，供玩家选择加入。
开发者工作
*必须提供玩家创建房间选项，内容为可用匹配池以及条件字段设置。
*收到玩家的房间列表请求时，向服务器查询，并将结果展示给玩家。
*调用 NetworkService.SendPacket，允许玩家向房间内的指定玩家发送消息。
*调用 NetworkService.SendPacketToCurrentRoom，允许玩家向房间内的所有其他玩家发送消息。
*调用 NetworkService.ReadPacket，允许房间内的玩家读取消息。
玩家体验
*玩家可设置创建选项，创建房间。
*允许玩家设置浏览选项，请求满足此选项要求的房间列表，并选择列表中的房间加入。
*玩家请求加入房间时，向服务器发送加入房间请求。

说明

Data Key

自定义数据的唯一标识，例如：Level。

数据类型

包括：
*浮点型
*整形
*十六进制

默认值

自定义数据的默认值。该默认值为兜底取值。
例如，你在代码中配置的参数（对应 Data Key）为  Level，取值 0 表示 20 级，取值 1 表示 30 级，且你在开发者平台为 Level 数据配置的默认值为 0。当一个无任何历史数据的新用户加入匹配时值，系统默认为其赋值 0，即默认其等级为 20 级。

只有添加自定义数据后，才可以添加匹配查询。



参数

说明

Query Key

匹配查询的唯一标识。

表达式权重

表达式的重要性等级，包括：必要、高、中、低，重要性等级依次递减。重要性越高，计算双方匹配度时的权重因子越小，其中 必要 = 0、高 = 0.55、中 = 0.75、低 = 0.9。
若双方条件无法满足 必要 表达式，则必定匹配失败。若双方条件满足 必要 表达式，但无法满足其余等级的表达式，则匹配结果根据所有表达式因子的乘积是否大于匹配度阈值决定。

表达式

表达式用于计算用户之间的匹配值。同一查询可由多个表达式构成，你可以给每个表达式设置权重。系统将按权重组合这些表达式的结果，得到最终的匹配值。
每个表达式的结果为布尔值：true 或 false：
*若结果为 true，该表达式产生因子 1。
*若结果为 false，该表达式产生一个小于 1 的因子（expression_val）。表达式的重要程度越高，则结果为 false 时产生的因子值越小。最终匹配值为所有所有表达式因子的乘积，即：最终匹配值 = expression_val_1 * expression_val_2 * ...* expression_val_n。
若 A 和 B 参与匹配，系统会分别以 A 指定的表达式和 B 指定的表达式计算出 匹配值 A 和 匹配值 B。其中，较小的匹配值将作为最终的匹配值。若匹配值大于匹配度阈值，则立刻匹配，否则需等待一定时间。
