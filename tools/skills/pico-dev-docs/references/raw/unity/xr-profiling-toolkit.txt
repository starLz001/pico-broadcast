XR Profiling Toolkit
========================================
PICO XR Profiling Toolkit Unity 包是一款自动化并可自定义的图形性能分析工具，用于测试并分析 XR 应用在头显设备上的运行效能。工具包的核心框架包括：自动化測试脚本、图形特性切换、分析数据导出和分析报告生成，以支持深度性能评估和跨设备对比。
开发者可以通过 Unity Package Manager 快速将此工具集成到已有 XR 项目中。同时，我们提供了开源的 VR 和 MR 高质量示例场景，用于展示工具包功能和用法。
*用
*XR Profiling Toolkit VR 和 MR 示例场景
*使用场景
*跨厂商性能评估：开发者可以通过 XR Profiling Toolkit 比较不同 XR 头显设备上的硬件能力，以及在同一场景下各设备的稳定性和性能开销。
*图形内容优化：帮助开发者就图形内容、渲染特性以及在不同头显上可实现的视觉质量做出决策，针对 XR 设备优化内容创作和资源规划。
*示例场景测试：为开发者提供高质量的 VR 和 MR 美术场景作为参考。这些示例场景也可作为测试平台，复现性能或功能问题。

*XR 功能设置
XR 功能设置文件位于 Packages/XR Profiling Toolkit/Settings/XRFeatureSettings，设置后将自动应用于所有场景。
* 
*Incompatible Features：指不能同时启用的功能组合。例如，Foveated Fixed Rendering（固定注视渲染）和自适应分辨率无法同时启用。默认情况下，没有任何功能被标记为不兼容。
*Foveation Level：设置注视渲染的强度等级。推荐使用中等级，以在画质和性能之间取得平衡。
*MSAA Samples：多重采样抗锯齿的采样数量。始终推荐使用 4x。
*Feature Status In Manual Mode：配置手动模式下启用的功能。在手动模式中，用户可以自由探索场景并与物体交互。推荐同时启用 MSAA 和 FFR。
*Target Resolution：设置渲染场景时的眼部缓冲分辨率。
*不同平台的缓冲区宽高可能略有不同，但总像素数量应接近。
*当前数值适用于主流设备；高端设备可设置更高分辨率。

*自动化测试
该工具包支持通过预设指令队列自动运行测试流程，并生成包含性能数据的报告，帮助开发者评估场景复杂度、识别性能瓶颈，或验证优化效果。
MR 示例场景的自动化测试功能目前仅支持在 PICO 4 Ultra 或 Meta Quest 3 设备上运行。
*Command Queue（指令队列）
Command Queue 用于存储场景的自动化操作序列。运行测试前，必须指定一个序列化后的指令队列。建议通过菜单：XR Profiling Toolkit -> Shortcut -> Copy Scriptfolder To Assets 将内置脚本复制到项目目录以便查看和调试。
*创建与编辑指令队列
要在 Unity 编辑器中创建 Command Queue（指令队列），请在 Project 窗口中右键点击并选择：Create -> XRProfilingToolkit -> Command Queue。
配置完成后，点击 Save to File 按钮，即可将当前的指令队列保存为 JSON 文件，以供后续使用。
你可以在以下路径中找到默认提供的三个指令队列示例资源：Package/XR Profiling Toolkit/Editor/ProfilingToolScripts/SampleCommandQueues。
若你点击菜单栏中的快捷项：XR Profiling Toolkit -> Shortcut -> Copy ProfilingToolScripts folder To Assets，这些示例指令队列资源将被复制到 Assets/XRProfilingToolkit/Editor/ProfilingToolScripts/SampleCommandQueues 文件夹中，方便查看与修改。
同样地，你还可以在以下目录找到三个指令队列的 JSON 文件示例：Package/XR Profiling Toolkit/Editor/ProfilingToolScripts/AutomationScripts 或 Assets/XRProfilingToolkit/Editor/ProfilingToolScripts/AutomationScripts。

*配置参数说明
*Id：当前指令队列的唯一标识符（建议使用语义化版本号格式 X.Y.Z）
*Stop Time：达到该秒数后中止整个测试流程
*Commands：包含所有测试流程命令的列表，支持以下类型：
*基本命令（适用于所有场景）
*CommandMove：以设定速度移动至目标位置
*CommandPause：暂停当前流程
*CommandWait：延迟指定秒数后执行下一个命令
*CommandScreenCapture：截图或录屏（支持多种采集类型）
*组件联动命令（需配套 Prefab）
*CommandLoadLevel：加载指定测试关卡（使用 SceneLoader）
*CommandToggleFeature：切换图形特性（如 FFR、MSAA、动态分辨率）
*Cyber Alley 特有命令
*CommandSetDynamicMode：设置粒子效果模式（0 无、1 粒子系统、2 VFX Graph）
*CommandTeleport：传送至预设锚点位置（0-4）
*Relic 特有命令
*CommandCreateSpaceItem：在 MR 空间中创建指定道具
*CommandSetLODLevel：设置所有道具的 LOD 等级
*CommandWaitForSceneCapture：等待场景截图完成

*分析方式
分析性能分析会话有两种方式：
*单场景报告（Generate Analysis Report）
*点击 Browse 按钮，选择生成的性能数据文件夹，或复制该文件夹的完整路径粘贴到命令输入框中。
*点击 Generate Analysis Report 按钮，工具会在所选的数据文件夹下生成一个名为 analyze_report 的文件夹，并自动打开本地网页进行展示。你也可以稍后通过点击 analyze_report 文件夹中的 index.html 文件手动打开报告。
*如果 Generate Analysis Report 按钮无法使用，你也可以点击 Copy Generate Analysis Command 按钮，将命令复制并粘贴到命令行终端中运行。
*对比报告（Generate Comparison Report）
*该功能用于将两个性能分析会话的结果进行对比，并在同一网页中展示。
*点击 Browse 按钮，选择另一个生成的性能数据文件夹，或复制该文件夹的完整路径粘贴到命令输入框中。此数据将与选择的 Profiling Data Path 进行对比。
*点击 Generate Comparison Report 按钮，工具将在性能数据目录中生成一个名为 comparison_report_{benchmark_session_directory_1}_{benchmark_session_directory_2} 的文件夹，并自动打开本地网页进行展示。你也可以稍后通过点击该文件夹中的 index.html 文件手动打开报告。
*如果 Generate Comparison Report 按钮无法使用，你也可以点击 Copy Generate Comparison Command 按钮，将命令复制并粘贴到命令行终端中运行。
*报告阅读指南
*顶部信息
显示测试名称、使用的指令队列 ID、设备型号和渲染设置。
* 
*指标图表
展示所有启用的指标图表（可切换），并显示平均值等摘要信息。
左侧的标签页用于切换配置的各项性能指标。每个标签页上会显示对应的指标名称及该会话的平均值。
* 
*屏幕截图对比
报告中会展示捕获的屏幕截图。具有相同上下文的截图会被自动分组。如下图所示，左右两张图用于对比：左图为基准版本，启用的渲染功能最少；右图则启用了部分额外的渲染特性。
* 
对比报告在以下几个方面与常规报告有所不同：
*如果两个会话在不同设备上运行，每个会话的设备规格信息将并列显示，便于对比分析。
*如果两个会话都包含相同的性能指标数据，该数据将被绘制在同一张图表上，并在标签页中显示两个会话各自的平均值。
*截图只有在具有相同上下文和渲染功能配置时，才会并排显示用于对比。
*将 XR Profiling Toolkit 集成到其他项目中
若你希望将 XR Profiling Toolkit 移植到其他 Unity 项目中，可按以下最小步骤进行：
*通过 Window -> Package Manager -> Add package from disk 导入 XR Profiling ToolKit 包。或从 Unity Asset Store 导入。
*在 Unity 编辑器菜单中点击 XR Profiling Toolkit -> Shortcuts -> Validate Provider Plugin (Meta/PICO)。此操作会自动检测项目中已集成的 XR SDK（如 Meta 或 PICO），并启用对应平台所需的功能代码。
*点击 Add CommandRunner To Scene，将核心运行组件 CommandRunner.prefab 添加至场景。你也可手动创建一个空 GameObject，并将 CommandRunner.cs 脚本挂载其上。
*创建并配置 Command Queue。请按照 “自动化测试” 部分的说明，在你的 Unity 项目中创建指令队列。需要注意的是，当前仅支持有限的一组指令，因为部分指令依赖其他系统。不过，你也可以参考现有指令，自定义适合你项目需求的新指令类型。详见 “配置参数说明” 部分。
*构建并部署项目。构建并部署你的 Unity 项目，将 APK 文件安装到设备上。之后，你可以按照“自动化测试”部分的说明运行性能分析会话并生成性能报告。
