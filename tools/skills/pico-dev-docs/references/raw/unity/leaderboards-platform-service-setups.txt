实现流程
========================================
本文档介绍如何在应用内实现排行榜服务。
*重要提示
*目前暂不支持在 Unity 编辑器中测试排行榜服务。
*前提条件
*已在项目中导入 PICO Unity Integration SDK 并完成项目配置。若未完成，参考以下文档完成该任务：
*导入 SDK
*完成项目配置
*实现流程
*第一步：创建排行榜

*在 我的应用 页面上，点击目标应用卡片，进入其 概览 页。
*在左侧导航栏中，点击 平台服务。 
*你将前往 PPS 开发平台。
*在左侧导航栏中，点击 排行榜。
*你将进入排行榜管理面板。
*点击 创建排行榜。
*你将进入排行榜配置面板。

*选择排行榜的展示语言。

*常见问题 
API Name 一致时，如何指定“中国大陆”或“非中国大陆”地区的排行榜？ 
在开发者平台同时为“中国大陆”和“非中国大陆”地区创建排行榜时，可以为两个排行榜设置相同的 API Name。 
这种情况下，若你调用的是客户端接口，则 SDK 会根据登录帐号所属地区进行判断并查询对应的排行榜。若你调用的是服务端接口，由于两个地区的服务端域名不同，所以系统会根据域名进行判断并查询对应的排行榜。 



参数

说明

显示名称

应用内向用户展示的排行榜名称。

API Name

排行榜的唯一标识，即接口中需传入的 leaderboardName 参数。

排序方式

指定排序方式。选项有： 
*越高越好 （默认）：降序排列，数值越高，排名越靠前。常使用于积分类应用。 
*越低越好 ：升序排列，数值越低，排名越靠前。常使用于竞速类应用。 

排序字段类型

指定排序字段类型。选项有：距离（英尺）、 距离（米）、 百分比、得分（默认）、 时间（毫秒）、 时间（秒）。其中： 
*距离：常用于竞速类应用。例如：时间恒定的赛车游戏。 
*百分比：可用来对胜率、击杀率、命中率等进行排序。 
*得分：常用于积分类应用，例如：卡牌游戏。 
*时间：常用于竞速类应用。例如：距离恒定的赛车游戏。 

数据写入权限

指定排行榜数据写入权限。选项有： 
*客户端可写入（默认）：客户端和服务端都可以写入数据。 
*仅服务端可写入：只有服务端可以写入数据 

关联 Destination

是否将排行榜与 Destination（某个关卡、地图等）关联。关联后，用户可通过排行榜跳转至所关联的 Destination，你需要自行为排行榜 UI 设计跳转按钮。选项如下：
*否 （默认） 
*为当前应用所配置的所有 Destination 的显示名称，按首字母排序 
提示：若未配置 Destination，则下拉项仅为 否。关于创建 Destination 的具体步骤说明，参阅此文档。

是否启用好友排行

若启用，用户将能够在此排行榜上看到好友的排名。

是否启用通知

启用好友排行后，可选择是否启用通知。启用后，当用户的排名被好友超越时，该用户将在设备端的通知中心收到通知。点击通知区域后，系统将启动相关应用并将用户跳转至该应用。



接口

说明

LeaderboardService.Get

获取指定排行榜的信息。

LeaderboardService.GetEntries

获取排行榜的条目数据，包括排行榜条目的显示分数、排行榜条目的补充数据、排行榜条目的ID、排行榜条目的排位等。

LeaderboardService.GetEntriesAfterRank

获取某个排行榜中指定排序之后的条目数据。

LeaderboardService.GetEntriesByIds

获取某个排行榜中指定用户的条目数据。

LeaderboardService.WriteEntry

为排行榜写入一条条目。

LeaderboardService.WriteEntryWithSupplementaryMetric

为排行榜写入一条条目，条目内可以包含用于决胜局的额外指标。
