# PICO 开发者 SDK 文档研读纪要（developer-cn.picoxr.com）

> 研读对象：PICO 开发者门户 7 个文档库，共 **613 页正文**（全部归档 `raw/`）。
> 与《PICO 官方文档研读纪要》（企业服务站 83 篇）的关系：**企业站管"管控"（TobService/套件/串流/MDM），开发者站管"内容开发"（游戏怎么写、怎么打包、怎么渲染）**。本项目两边都要用。

## 1. SDK 版图与选型

| 平台 | 路线 A：Integration SDK | 路线 B：OpenXR 插件 | 说明 |
|---|---|---|---|
| Unity | PICO Unity Integration SDK（`unity/` 237 节点 + `pico-unity-quickstart` 39 节点） | Unity OpenXR + PICO OpenXR Feature（`pico-unity-openxr-guide` 33 节点） | Integration 功能最全（注视点渲染/合成层/企业特性）；OpenXR 通用性最好 |
| Unreal | PICO Unreal Integration SDK（`unreal/` 180 节点 + `pico-unreal-quickstart` 27 节点） | PICO OpenXR 插件（`pico-unreal-openxr-guide` 61 节点） | 另有 PICO 维护的 UE 分支（PICO-fork-of-ue） |
| 空间应用 | PICO Spatial SDK（`spatial-sdk/` 171 节点） | — | **基于 Android 体系、跑在 PICO OS 6 上**的新形态应用框架 |

## 2. 关键事实（原文核实）

### 2.1 Unity Integration SDK

- 支持设备：Neo3 系列 / PICO 4 系列 / PICO 4 Ultra 系列
- Unity 编辑器：最低 2021.3.26，最高 Unity 6.3，推荐 LTS
- 版本配套红线：
  - Unity 2022 → SDK ≥ 2.1.5 且 PICO OS ≥ 5.5.0
  - Unity 2023 → SDK ≥ 3.0.0 且 PICO OS ≥ 5.11.0
  - Unity 6 → SDK ≥ 3.1.0 且 PICO OS ≥ 5.12.0
- 设备系统版本：PICO 4 系列需 OS 5.13.0；PICO 4 Ultra 系列需 OS 5.14.0+
- 已知坑：Unity 2022 + URP + Linear + 4xAA + OpenGL 崩溃；Unity 2022 + Vulkan + Development Build 崩溃
- 功能域：渲染（FFR/ETFR/合成层/多视图/超分/锐化/URP）、交互（手柄映射/手势/眼动/触觉/系统键盘）、平台服务、Avatar 等

### 2.2 Unreal Integration SDK

- 开发机：Windows 10，CPU i5-4590/R5 1500X+，显卡 GTX 1060/RX 480+，8G+ 内存，USB 3.0
- 设备：Neo3 系列 / PICO 4 系列 / PICO 4 Ultra
- UE5 特性支持有专篇（`ue5-feature-support`）；PICO 维护虚幻引擎分支（`PICO-fork-of-ue`），深度集成项目可用
- 功能域与 Unity 对齐：渲染（FFR/自适应分辨率）、交互、平台服务

### 2.3 OpenXR 路线（Unity/UE 都有）

- 定位：跨厂商标准 API；PICO 以 OpenXR Feature/插件形式提供扩展（手势、眼动、体感追踪等）
- 选型建议：**内容方已有项目用什么就继续用什么**；新上车的 Unity 项目优先 OpenXR（未来性好），需要 PICO 深度特性（合成层视频、企业特性）再上 Integration

### 2.4 Spatial SDK（PICO OS 6 新形态）

- 基于 Android 体系 + Jetpack Compose（Spatial UI），开发"空间应用"：空间容器、环境感知（锚点/网格/平面检测）、多模态交互（眼/手/柄/键盘）
- 配套：Spatial Toolkit（Android Studio 插件 + 模拟器）、SpatialML（相机+ML 图运行时）、WebSpatial（Web 技术栈跨平台）
- **与本项目的关系**：不是一期必需品。潜在用途——头显端待机页/门店 Launcher 未来可用 Spatial UI 做成 OS 6 原生空间界面；Agent 本体仍是普通安卓服务。

## 3. 与本项目的接口点（谁用哪套）

| 端 | 用哪套 | 说明 |
|---|---|---|
| 内容端游戏（一体机 APK） | Unity/UE Integration SDK 或 OpenXR（**内容方现状决定**） | 我们的播控 SDK 是额外内嵌的轻量库，与 PICO SDK 不冲突：PICO SDK 管 XR 渲染交互，我们管场景直达/指令/令牌/数据回传 |
| 内容端游戏（串流 PC 版） | **不用 PICO SDK** | PC 版是普通 UE/Unity 工程，画面经企业串流 SDK 传输 |
| 控制端 PC/Pad | Unity 普通 2D 工程 | 不需要 PICO XR SDK |
| VR Agent | 原生 Kotlin + TobService | 不用本站任何 SDK |
| 头显待机页/Launcher（三期可选） | Spatial SDK | 等 OS 6 普及再评估 |

## 4. 打包与合规要点（内容交付时用）

- 包名命名规范专篇（`naming-conventions-for-app-package-name`）——企业分发也建议遵守，避免与商店规则冲突
- Android Manifest 配置专篇；项目配置验证工具（project-validation）可在打包前自查
- 注意区分：PICO XR SDK 的 manifest 配置 vs 我们 Agent 的 `pico_advance_interface` 高风险声明是**两套独立机制**——游戏 APK 不需要高风险声明（除非要调 TobService），Agent APK 需要
