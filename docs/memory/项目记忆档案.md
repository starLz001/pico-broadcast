## 1. 项目背景与商业模式

- 自研 PICO 播控系统：管控 UE / Unity 开发的 VR 游戏内容与设备。
- 设备：PICO 未发布新设备 + PICO 4 Ultra Enterprise（PICO4UE）。
- 商业模式：平台方（用户方）把系统交付**运营方**使用，按**启动次数向运营方收费**；平台方保留设备与程序的最高管控权。
- 路线：自研四块（VR Agent / 控制端+本地服务 / 轻云端 / 内容 SDK），复用 PICO 官方能力（TobService、企业串流、录屏直传），不重复造轮子。

## 4. 架构快照

四端 + 三条链路（详见 `01-架构设计/` 图纸与文档）：

- **门店本地**：控制端 PC/Pad + 本地服务（同机）——内容库存储、局域网中转、监看中继、账本缓存
- **轻云端**：账号授权 / 额度中心 / 账本归集 / 汇总看板 / 冻结 / 审计
- **VR Agent**（每台头显，Kotlin，Device Owner 常驻）：指令通道、管控执行、前台监听、加密记账、额度校验、画面采集、防篡改、串流适配
- **内容 SDK**：Unity 插件 + UE Java 桥接；场景直达、游戏内深度控制（切关卡等）、运行数据回传、运行令牌校验
- 串流主机：独立 PC，跑 PCVR 内容 + 伴生程序（抓帧、进程监听、记主账）

## 5. 计费与额度口径（收费红线，勿擅改）

- 启动次数 = 收费依据：ACK 确认拉起记 1 次。
- 单次时长 = 前台监听的内容前台停留时间。
- 异常启动（绕过播控手动开）照样计费 + 告警，账单标 source=manual_detected。
- 免单：时长 ≤ 阈值免单（R11），不限次数；免单局记账标 trial；时长计入统计。
- 额度耗尽：拒绝启动 + 锁内容 + 红色回路通知平台方充值调额。
- 冻结优先于一切本地额度。
- 风险留底：不限免单次数可能被"反复短时重开"薅羊毛；云端规则可配，必要时改为每日限免 N 次（无需改设备端）。

```
                    ┌─────────────────────────┐
                    │ 总管理 Agent（Kimi）      │  技能：spec-owner
                    │ 需求沟通·任务卡签发        │  + pico-enterprise-docs
                    │ 技术把关·验收裁决·记忆维护 │
                    └───────┬─────────┬───────┘
              签发任务卡     │         │  双份报告汇总裁决
        ┌───────────────────┘         └───────────────────┐
┌───────▼────────┐                              ┌─────────▼────────┐
│ 实现 Agent ×N   │  实现完成自测                  │ 测试 Agent（独立） │  技能：qa-tester
│ （Claude Code） │ ────────────────▶            │ （Claude Code）   │  + pico-enterprise-docs
│ 按模块可并行：    │   代码+自测报告                │ 只测不修：         │
│ agent-android / │                              │ 仿真器互通·用例覆盖 │
│ server /        │                              │ 真机清单执行       │
│ controller /sdk │                              │ 发现 bug 只报告    │
└────────────────┘                              └──────────────────┘
        用户：需求拍板 + 真机操作 + 在两侧之间传递代码/报告
```

- **总管理（Kimi，我）**：唯一与用户对接需求；出任务卡与仿真器；裁决实现 Agent 与测试 Agent 的报告；维护本档案。
- **实现 Agent**：按任务卡实现，不得改规格，矛盾走 STOP 流程。
- **测试 Agent**：独立实例，只写测试不改实现；验收标准逐条对应 PASS/FAIL；真机清单逐条打勾附证据。
- 并行规则：同一模块的实现与测试不可由同一实例完成。
